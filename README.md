# 북끄럽 아카이브

독서모임 **북끄럽**의 회차별 모임지를 모아 두는 곳입니다.

매번 새로 만든 모임지가 모임이 끝나면 흩어져서, 그날 어떤 이야기를 나눴는지 다시
찾아볼 수가 없었습니다. 책과 날짜, 이야깃거리를 한곳에 쌓아 두고 언제든 다시
읽을 수 있게 만들었습니다.

## 무엇을 할 수 있나

- **책장** — 읽은 책이 책등으로 꽂힙니다. 두께는 쪽수, 색은 제목에 따라 정해집니다.
  연도별로 한 칸씩, 제목·저자 검색과 요일(화요/목요/토요) 필터가 있습니다.
- **모임지** — 이야깃거리가 포스트잇으로 깔립니다. 눌러서 질문 전문과 그 아래
  오간 이야기를 봅니다.
- **댓글** — 로그인 없이 닉네임만 적고 남깁니다. 질문마다, 그리고 모임 전체에.
- **추천 도서·영화** — 모임 중에 자연스레 나온 추천작을 따로 모아 둡니다.
- **등록** — 이야깃거리를 줄글 그대로 붙여넣으면 질문 단위로 나눠 줍니다.
- 홈 화면에 추가하면 앱처럼 열립니다 (PWA).

## 어떻게 만들어졌나

빌드 도구도 프레임워크도 쓰지 않습니다. 저장소에 있는 파일이 그대로 배포되는
파일입니다. 10년 뒤에도 열리는 것이 목표입니다.

- HTML / CSS / 바닐라 JS (ES 모듈)
- [Supabase](https://supabase.com) — Postgres + RLS
- GitHub Pages

```
├── index.html          책장
├── meeting.html        모임지 상세 (?id=…)
├── picks.html          추천 도서·영화
├── admin.html          모임지 등록
├── css/style.css
├── js/
│   ├── config.js       Supabase 주소와 공개 키
│   ├── supabase.js     클라이언트 하나만 만들어 공유
│   ├── api.js          DB 읽기·쓰기. DOM은 건드리지 않는다
│   ├── parser.js       줄글 → 질문 배열 (순수 함수)
│   ├── shelf.js        책등 치수·색 계산 (순수 함수)
│   ├── mask.js         이름 가운데 가리기
│   ├── profanity.js    욕설 걸러내기
│   ├── nickname.js     닉네임·익명 ID (localStorage)
│   ├── ui.js           공용 조각
│   ├── booksearch.js   Google Books 조회 (등록 화면 전용)
│   ├── install.js      앱 설치 안내
│   └── page-*.js       화면별 진입점
├── supabase/schema.sql 테이블 + RLS 정책
└── sw.js               서비스워커
```

`parser.js`와 `shelf.js`는 DOM도 DB도 모르는 순수 함수입니다. 이 프로젝트에서
틀리기 쉬운 로직이 여기에 몰려 있어서, 따로 떼어 두고 테스트합니다.

## 데이터

| 테이블 | 쓰임 |
|---|---|
| `meetings` | 날짜, 책 제목, 저자, 쪽수, 고른 사람, 이야깃거리(jsonb) |
| `comments` | 질문별(`q:0`) 또는 전체(`overall`) 댓글 |
| `picks` | 모임 중에 나온 추천 도서·영화 |

질문은 별도 테이블로 쪼개지 않고 `meetings.questions`에 배열로 넣습니다.
모임지는 항상 한 장 통째로 읽고 쓰지, 질문만 따로 조회할 일이 없습니다.

## 권한

로그인이 없습니다. 대신 DB의 RLS 정책이 할 수 있는 일을 정합니다.

| 테이블 | 읽기 | 등록 | 수정 | 삭제 |
|---|---|---|---|---|
| `meetings` | 누구나 | 누구나 | 누구나 | 불가 |
| `picks` | 누구나 | 누구나 | 누구나 | 불가 |
| `comments` | 누구나 | 누구나 | 본인·30분 이내 | 본인·30분 이내 |

삭제 정책을 아예 만들지 않았기 때문에 모임지는 사이트에서 지울 수 없습니다.
잘못 올린 회차는 Supabase 대시보드에서 직접 지웁니다. 누가 한 번에 전부
지워버리는 일을 막기 위한 선택입니다.

댓글의 "본인"은 브라우저가 처음 방문할 때 발급해 `localStorage`에 둔 임의의
문자열(`anon_id`)로 판별합니다. 이 값은 브라우저가 스스로 보내는 것이라 위조할 수
있습니다. 신원 증명이 아니라 오타를 고치기 위한 장치이고, 30분 제한은 그 위조가
통하는 범위를 최근 댓글로 좁힙니다.

`js/config.js`의 키는 공개용(publishable)이며 브라우저에 그대로 노출됩니다.
정상입니다. 실제 권한은 위 정책이 정합니다. `service_role` 키와 secret 키는
저장소에도 코드에도 넣지 않습니다.

## 직접 띄워보려면

```bash
python3 -m http.server 8000
```

`http://localhost:8000` 을 엽니다. 빌드 단계가 없어서 파일을 고치고 새로고침하면
끝입니다. 로컬에서는 서비스워커 캐시가 꺼져 있어 수정이 바로 반영됩니다.

새 Supabase 프로젝트에 연결하려면:

1. 프로젝트를 만들고 SQL Editor에 `supabase/schema.sql`을 붙여넣어 실행합니다.
2. Settings → API 에서 Project URL과 publishable 키를 `js/config.js`에 적습니다.

## 알아둘 것

- **모임지 링크는 개별 미리보기가 뜨지 않습니다.** 카카오톡·페이스북은 링크를 읽을
  때 자바스크립트를 실행하지 않고 HTML만 봅니다. 정적 사이트라 회차별 HTML을 미리
  만들어 둘 수 없어서, 어느 회차를 공유하든 공통 카드가 나옵니다.
- **욕설 필터는 완전하지 않습니다.** 자음 분리(ㅅㅂ), 숫자 끼워넣기(시1발) 정도는
  잡지만, 브라우저에서만 도는 검사라 우회할 수 있습니다.
- **Google Books는 한국어 책 정보가 자주 빕니다.** 쪽수를 못 찾으면 비워 두고,
  책장에는 기본 두께로 그립니다. 나중에 직접 채워 넣을 수 있습니다.
